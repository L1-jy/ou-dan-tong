# 03_演示数据 · 队友B 工作区

> 职责：造出"有真实感、有陷阱"的温州中小企业业务群聊，供智能体演示与回归测试。
> 不需要任何代码能力，用普通文本/表格写即可。

## 一、数据要覆盖的 4 类场景（每类 ≥ 2 条）

| 类型 | 说明 | 演示目的 |
|---|---|---|
| 正常成交 | 客户询价→报价→确认，要素齐全 | 展示"乱中取单"主流程 |
| 缺信息 | 只说产品没说数量/没说责任人 | 验证智能体"跳过并提示人工确认"，不瞎编 |
| 冲突/改单 | 同一单前后数量/交期说法不一、或客户改需求 | 验证变更捕获 + 履历留痕 |
| 异常 | 负数数量、过去的交期、明显不合理 | 验证异常拦截 |

> 宗旨：评委点名要"缺失·冲突·异常怎么处理"——你的数据就是用来证明这点的。

## 二、怎么写（参考模板）

每条数据包含 3 个字段，存为 Markdown 或文本即可：

```
【场景名】乐清某电器厂-客户催单改数量
【群聊文本】
王工：李经理，NMX-60 那批数量改一下，改成 6000 个
李经理：好，我更新下台账
【预期结果】
- 命中已有单 ORD-xxxx，数量 5000 → 6000
- changes 新增一条变更履历（谁、何时、改了什么）
- 交期是否需要重估应被追问
```

## 三、放置位置

- 新数据写到本目录，建议命名：`场景1_正常成交.md`、`场景2_缺信息.md`……
- 需要给代码用的结构化样例，由队长/AI 助手转成 `02_智能体代码/ou_dan_tong/sim_chats.py` 里的 Python 变量。

## 四、验收

- 每条数据都能在 `02_智能体代码/ou_dan_tong` 跑通（贴入网页 → 看台账/提示是否符合预期）。
- 至少包含 1 个"动态更新"案例：先一条消息建单，再一条新消息改单，验证增量更新。
