# 03_演示数据 · 模块一（模拟数据构建）｜队友A 工作区

## 一、模块目标

为瓯单通智能体提供**可直接导入、有真实感、有陷阱**的温州中小企业业务群聊模拟数据，用于：

1. 模块二（变更识别与记录）联调：抽取、变更关联、缺失/冲突/异常分支的输入；
2. 模块四（查询应答）验证："返回最新状态而非旧版本"的事实基础；
3. 模块五（测试验证）走查：五类场景 + 动态演进逐个断言。

红线：全部为自建模拟数据，不涉及任何真实企业信息；企业名均作化名处理（如"永嘉××精密机械"）。

## 二、功能需求（对应开发任务清单 模块一·1~4）

| 编号 | 需求 | 本模块落地 |
|---|---|---|
| 模块一·1 | 确定场景覆盖清单（五类） | 见下方"场景清单"，5 类 + 动态演进共 11 组，每类标注预期校验结果 |
| 模块一·2 | 编写口语化群聊文本（非正式、信息残缺、多别称；每类 ≥2 组） | `data/chat_logs.json` 内 5 类场景各 2 组（S1~S5 共 10 组） |

## 三、交付标准

### 3.1 输出约定（契约 1：聊天输入格式，与接口约定文档一致）

每条消息统一为：

```json
{
  "group": "群名",
  "speaker": "发言人",
  "time": "2026-10-20 14:30",
  "text": "原始口语化聊天内容"
}
```

- 一个 `groups[]` 数组项 = 一个场景组（同一群、按 `time` 升序的多条消息）；
- 每项含场景元数据：`scene_id` / `scene_type` / `title` / `notes[]`（陷阱提示）/ `expected`（预期抽取结果 + `validator_target`）。
- `expected.validator_target` 直接对应接口约定的校验结果 `status`：`ok | missing | conflict | abnormal`，供模块五断言。

### 3.2 边界条件

- 时间戳统一 `YYYY-MM-DD HH:MM` 24 小时制，组内单调递增；允许跨天（动态演进）。
- 口语化要求：允许别称（"法兰"≈"304法兰盘DN80"）、残缺（"那批"）、口语时间（"周五"“下周”"月底前"）。
- 场景隔离：不同组使用不同客户/产品组合，避免跨场景实体污染。
- 生成器为确定性输出（无随机），重复运行结果一致，便于回归。

### 3.3 验收指标（运行 `gen_sim_chats.py` 自动校验）

| # | 指标 | 阈值 |
|---|---|---|
| A1 | 场景覆盖 | 5 类场景各 ≥2 组；动态演进 ≥1 组 |
| A2 | 消息结构 | 每条含且仅含 `group/speaker/time/text` 四键，均非空 |
| A3 | 时间序 | 组内消息按 time 升序，无逆序 |
| A4 | 组规模 | 总组数 ≥11，每组消息 ≥2 条 |
| A5 | 实体可关联 | 每组含明确实体线索（单号/客户+产品），供模块二主键匹配 |

校验失败时进程以非零码退出并输出明细。

## 六、使用与扩展

```bash
# 生成数据 + 自动校验（失败非零退出）
python gen_sim_chats.py

# 仅校验已有数据
python gen_sim_chats.py --check-only

# 指定输出目录
python gen_sim_chats.py --out ./data
```

新增一组：在 `gen_sim_chats.py` 的 `GROUPS` 列表追加一个字典（scene_id / scene_type / title / group / messages / notes / expected），重跑生成器即可；`messages` 保持 `(speaker, time, text)` 三元组、时间升序，自检会自动覆盖新组。
